# Generated document security corpus

## Purpose

FullWorth exercises malformed and resource-hostile statement inputs without retaining uploaded statements, customer documents, screenshots, names, account numbers, balances, addresses, or other user data. Every corpus member is generated deterministically from source code during the test process.

The corpus is a parser-safety regression suite. It proves that currently represented malformed inputs fail closed at a bounded admission or managed parsing boundary. It is not a malware-detection engine and does not prove that every unknown PDF, image decoder, native-library, or kernel vulnerability is contained.

## Coverage

The generated PDF set covers:

- a PDF signature followed by a non-document body;
- a catalog without a page tree;
- an xref table whose root object does not exist;
- a stream declaring an integer-maximum length;
- invalid ASCIIHex stream bytes;
- invalid Flate stream bytes.

Every PDF case must surface only FullWorth's fixed safe extraction message. The test does not expose parser exception text, the generated case name, document bytes, or a storage path.

The generated image set covers:

- truncated PNG signatures and IHDR chunks;
- zero and excessive PNG dimensions;
- invalid PNG bit-depth/color combinations;
- unsupported PNG compression, filter, and interlace methods;
- a corrupted PNG IHDR CRC;
- truncated JPEG segments;
- JPEG scan data before a start-of-frame marker;
- zero and excessive JPEG dimensions;
- an undersized JPEG start-of-frame segment.

Every image case must be rejected before native image decoding or OCR and must return a zero admitted pixel count.

## Production hardening

PNG admission now validates the complete fixed 13-byte IHDR payload and its CRC before calculating pixels or allowing native decode. Width and height must be non-zero, bit depth must be legal for the declared color type, compression and filter methods must be zero, and interlace must be zero or one. The existing conservative working-set estimate then rejects dimensions whose decoded expansion exceeds the admission ceiling.

JPEG admission continues to parse only bounded marker headers until a valid start-of-frame segment, rejecting truncation, invalid lengths, scans without dimensions, zero dimensions, and decoded working-set expansion.

These checks are admission controls. Accepted files remain untrusted and execute only through the separately documented parser-worker and per-document/per-image cgroup boundary.

## Data and size rules

Corpus cases live in `GeneratedMaliciousDocumentCorpus.cs` as generated byte arrays. The regression suite requires:

- unique lower-case descriptive names;
- only PDF, PNG, and JPEG media/extension pairs;
- at most 4 KiB per case;
- deterministic names and bytes across independent generation;
- no checked-in binary corpus artifacts.

A future case must be minimized to the smallest synthetic bytes that reproduce the parser condition. Never derive a fixture from a real statement, production log, customer upload, provider response, or private evaluation corpus.

## Change procedure

When a parser or native-library defect is found:

1. create a minimal deterministic generator with no user-derived bytes;
2. give it a behavior-based name rather than a vulnerability submitter or customer name;
3. assert the expected fail-closed boundary and sanitized result;
4. document any production admission change;
5. run backend tests plus exact-head dependency security;
6. run the production-container gate when Docker, parser-worker, native OCR, or containment behavior changes.

Repository tests are not production evidence. Deployment and claims about the exact running release require separate guarded-host verification.
